# Decisions

**D1. A fixed workflow under a Director, not free-form agent chat.** The spec judges the process. A fixed sequence of stages, each with one owner, a critique after every stage and logged hand-offs, makes the process inspectable and comparable across runs. Agents still decide content at each stage.

**D2. Citations are verified by an independent resolver, not by the agent's own records.** The verifier re-resolves each identifier through the indexes and compares title, first author, year and quote with what comes back. The agent cannot make its own citations look verified.

**D3. Layered layout instead of the planned force layout.** DESIGN first called for a seeded force layout. The graph is a stage pipeline, so a layered layout (one column per stage, barycentre ordering) reads left to right like the workflow, is deterministic without a seed, keeps keyboard movement predictable (up/down within a stage, left/right across stages) and needs no layout library. DESIGN was updated.

**D4. A rule-based reasoner as baseline.** Without a language model the system still runs end to end: query planning from the question's concepts, BM25 evidence selection, gap rules over concept co-occurrence, hypothesis and design from a person-written operationalisation per question. This gives a defensible baseline and lets everything run offline in CI. Its advantage is stated plainly: the operationalisation is written by a person, so its designs are not the baseline's own reasoning. It is labelled "Rule baseline (no language model)" wherever it appears.

**D5. Experiments limited to a fixed toolbox.** Agents design experiments by naming datasets, models, modifiers, metrics and a test from a catalogue; the toolbox runs them with stratified cross-validation, bootstrap intervals, paired tests and Holm correction. Agents cannot run arbitrary code, so every number is produced by audited code, and a hypothesis outside the toolbox is rejected at design time instead of being approximated. Leakage is prevented by construction: every modifier is fitted inside the training fold, so the planned "design with leakage" fault cannot be expressed and is not injected in E3.

**D6. Rule critic plus optional model critic.** Structural checks need no model and cannot be talked round by fluent text. Semantic checks (does the quote support the claim?) need judgement and are left to the model critic and the person. E3 includes semantic faults on purpose to measure what the rule critic misses.

**D7. Human corrections are counted only when a person reviewed.** A stage nobody reviewed reports "no review", not 0, so an unreviewed run cannot look like a flawless one.

**D8. Content-addressed retrieval cache and a transcript for model calls.** Runs record every index response and every model prompt and answer. Replay re-executes everything downstream, so reproducibility is measured (E5) rather than assumed.

**D9. Novelty by TF-IDF only.** PLAN listed TF-IDF and embedding similarity. Embedding models cannot be downloaded in this environment (model hubs are blocked), so only the TF-IDF indicator is computed. It is labelled an indicator, not proof.

**D10. Network and API key blockers (2026-10-08).** The environment's network policy blocks every scholarly index and no `ANTHROPIC_API_KEY` is configured. Everything that can be built and tested without them is built and tested on invented fixtures labelled as such. No end-to-end result, experiment result or screenshot from a run is reported until a real run exists.

**D11. Report fluency is scored on a template report.** The report renderer (`report.py`) writes the report from the artefacts only, so E4's corrupted variants differ in content but not in style. That isolates the question "does the process change how the report reads?" A model-written report would add stylistic variance on top.

**D12. Rate limits are "could not check", not "not found" (2026-10-08).** The first live E1 run met HTTP 429 from Semantic Scholar (shared IP) and OpenAlex (daily credit used up). Before the fix a 429 was cached and read as "no record", which would have counted real citations as unresolvable. Requests now retry with backoff (Retry-After honoured up to 60 s); a persistent "try later" makes the verifier report `unverifiable`, which is excluded from the citation-accuracy denominator and reported as a count, and E1 records per-source unavailability.

**D13. Replay serves the response versions a run consumed (2026-10-08).** The first E5 (results/e5_reproducibility/20261008T142701Z-bf1cf81) replayed 0/3 runs with identical verification: every artefact matched, but five quotes were additionally found in Semantic Scholar text, because a later E2 run in record mode had refetched requests the E1 runs had seen rate-limited, and replay served the newer answer. The cache now archives replaced responses instead of overwriting them, each run writes `retrievals.json` (which version of each response it consumed), and E5 replays from that manifest. E1 to E5 were rerun after the fix; the earlier result directories are kept as the record of the defect.

**D14. Online-first versus issue year.** In E1 one real citation (Bentham Science, DOI 10.2174/0126662558347788241127051934) failed the year check: OpenAlex and Semantic Scholar give 2024 (online first), Crossref gives 2026 (issue). The verifier's tolerance is one year. This is reported as a verifier false rejection, not tuned away after seeing the result.

**D15. Two E1/E2 findings kept as findings.** (a) E2's "wrong first author" corruption once picked another paper by the same author (Taeho Jo), so the "corrupted" citation was in fact correct and was accepted. That is a harness defect, not a verifier miss: the corruption now draws only authors with a different surname, and E2 was rerun. (b) One real citation in E1 (DOI 10.52465/joscex.v1i1.7) failed the author check because Crossref, the first authoritative resolver for DOIs, returns no author for it. The verifier treats a missing author at the source as a mismatch. That is a false rejection in the conservative direction and is reported, not tuned away.

**D16. A quote is "unchecked" when its own source was down (2026-10-09).** Reproducing E1 from a fresh clone, arXiv answered 429 to 8 requests (requests were spaced 1 s apart; arXiv asks for 3 s, now enforced). Two quotes taken from arXiv abstracts were then looked for only in Semantic Scholar's text, not found, and counted as wrong quotes; six citations were "could not check" but still counted against evidence correctness. A quote that is not in the text of the sources that answered, while another source was unavailable, is now `unchecked`, and evidence correctness, like citation accuracy (D12), is computed over evidence that could be checked, with the unchecked count reported. The committed E1 results had no unavailable resolver, so their values are unchanged.

**D17. The model arms run on a local open-weights model (2026-10-09).** No `ANTHROPIC_API_KEY` reached any build session, and the owner asked for the project to be finished without the API. Hugging Face became reachable in the "research" environment, so the language-model reasoner, model critic and judges now also run on GGUF weights through llama.cpp on the CPU (`reasoners/local.py`), behind the same `messages.parse` call and the same prompts as Claude. Choices: the agents and model critic use **Qwen3-4B-Instruct-2507** (Apache-2.0), the strongest permissively licensed instruct model that runs at a usable speed on four CPU cores; the Q4_0 quantisation was chosen over Q4_K_M after measuring 13.7 against 8.6 generated tokens per second at the same prompt speed. The judges use **Phi-4-mini-instruct** Q4_K_M (MIT), a different model family, so the reasoner does not grade its own output. Output is constrained to each schema's JSON grammar; an unusable answer (cut off, or failing a constraint the grammar does not encode) is retried once and then fails the step, recorded as a failed run, never repaired. Sampling follows the model card (temperature 0.7, top-p 0.8, top-k 20) with a per-call seed written to the transcript; judges sample at temperature 0. Weights are identified by SHA-256 in `configs/models.sha256` and in each experiment's provenance. Consequences stated in the report: a 4-billion-parameter quantised model is far weaker than the model the study was designed for, so the results answer "what does a small open model do inside this process", not "what does a frontier model do"; the Claude arms stay in the configuration and are recorded as skipped until a key exists. The judge is itself a small model, so judged metrics (hypothesis rubric, quote support, convincingness) are weaker evidence than the independently verified ones and are reported as such.
